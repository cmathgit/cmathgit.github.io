# LLM Embedding Geometry: A Theological Case Study
Welcome to this exploration of distributional semantics! This repository provides a hands-on, verifiable look at how Large Language Models (LLMs) encode human language into high-dimensional vector space.

By querying raw embedding weights from popular local models via the Ollama API, this project demonstrates the mathematical realities of "word-math." We begin by verifying the classic NLP analogy (`King - Man + Woman = Queen`) and then push the boundaries of semantic geometry by testing complex theological concepts—culminating in an attempt to mathematically pinpoint the Christ vector using contextual data native to the biblical corpus.

# Repository Structure
This project is completely self-contained and relies on pure Python to prove the underlying geometry of LLM embeddings.

`analyzeEmbeddings.py`: A standalone Python math engine. It loads the raw embedding weights and calculates the resulting spatial coordinates using four distinct metrics: Cosine Similarity, Dot Product (Inner), Euclidean Distance (L2), and Manhattan Distance (L1).

`embeddings/`: To guarantee the integrity of this case study, this repository does not include pre-calculated weights. You will generate the raw semantic data yourself directly from the models. As an example, I have provided the classic `King`, `Man`, `Woman`, and `Queen` weights generated by the qwen3-embedding:0.6b model.

# Setup & Data Generation
To guarantee the integrity of this case study, this repository does not include pre-calculated weights. You will generate the raw semantic data yourself directly from the models.

To ensure cross-architecture validity, generate the vectors across three different state-of-the-art embedding models:
- Qwen3 (qwen3-embedding:0.6b - 1024 dimensions)
- Gemma (embeddinggemma:300m - 768 dimensions)
- Granite (granite-embedding:30m - 768 dimensions)

## 1. Install Ollama
If you haven't already, download and install Ollama to run models locally. Once installed, pull the three embedding models used in this study:
```cmd
ollama pull qwen3-embedding:0.6b
ollama pull embeddinggemma:300m
ollama pull granite-embedding:30m
```

## 2. Generate the Embedding Vectors

You need to generate embedding JSON files for 11 specific target tokens: `King`, `Man`, `Woman`, `Queen`, `God`, `Christ`, `Father`, `Son`, `Jesus`, `Savior`, `Anointed`.

Create an `embeddings/` folder in the root directory, with three subfolders: qwen3, gemma, and granite. 

### Method A: Windows CMD (cURL)
You can use the native Windows command prompt to send the tokens to the API and pipe the output directly into a JSON file. Be sure to escape the quotes properly:
```cmd
curl http://localhost:11434/api/embed -d "{\"model\": \"qwen3-embedding:0.6b\", \"input\": \"King\"}" > "embeddings/qwen3/king.json"

curl http://localhost:11434/api/embed -d "{\"model\": \"qwen3-embedding:0.6b\", \"input\": \"Man\"}" > "embeddings/qwen3/man.json"

curl http://localhost:11434/api/embed -d "{\"model\": \"qwen3-embedding:0.6b\", \"input\": \"Woman\"}" > "embeddings/qwen3/woman.json"
```
(Repeat this process for the remaining tokens and for the other two models).

### Method B: Postman
If you prefer a GUI, you can easily generate these files using Postman:

1. Create a new POST request to 
```http
http://localhost:11434/api/embed
```
2. Navigate to the Body tab, select raw, and set the type to JSON.
3. Paste the request payload: 
```json
{"model": "qwen3-embedding:0.6b", "input": "King"}
```
4. Click Send.
5. Click Save Response > Save to a file and save it as king.json in your respective model folder.

## 3. Run the Math Engine
Once your vectors are generated and saved, simply run the Python script to execute the word-math and analyze the geometry!
```cmd
python analyzeEmbeddings.py
```

## Our Assumption Failed: `King - Man + God` is not similar to `Christ`  
This is a brilliant "failed" experiment and an absolutely incredible case study in semantic bias! The math didn't fail; the semantic logic of our equation failed to account for Christian theology, and the embedding models exposed our logical error perfectly.

### Why `King - Man + God` failed:
In the classic equation (`King - Man + Woman = Queen`), subtracting `Man` removes the concept of "male humanity," leaving the pure concept of "Sovereign/Royalty." Adding `Woman` applies that sovereignty to a female, yielding `Queen`. However, if we apply that to `Christ`:
1. **`King - Man`**: This extracts "Sovereignty" but explicitly **removes humanity**.
2. **`+ God`**: This adds divinity to our non-human sovereign.
3. **The Result**: We end up with a concept representing a purely divine, non-human king (which maps closer to God the Father or perhaps a Seraphim).

Because orthodox Christian theology defines `Christ` through the **Hypostatic Union** (being fully God *and* fully man), subtracting `Man` actually pushed our vector *away* from `Christ`! `Christ` is the "Son of Man," so humanity must remain in the equation.

### Better Semantic Equations:

1. **The Hypostatic Union:** `God + Man = Christ`
*(Combining the divine and human natures directly).*
2. **The Messianic Sovereign:** `God + King = Christ`
*(Adding divinity directly to an earthly sovereign without stripping away the humanity).*

## The Problem with `God` and `King`
While `God` and `King` are heavily associated with `Christ`, they are also highly generalized. `God` applies to the Father, the Holy Spirit, and false idols (e.g., "god of this world"). `King` applies to David, Solomon, Herod, and Nebuchadnezzar. These generalized contexts create "drag" on the vector, slightly altering its trajectory away from the precise coordinate of `Christ`.

To break the 0.86 threshold, we need sharper vectors. Here is an analysis of three highly specific equations designed to mathematically pinpoint the `Christ` vector:

### Hypothesis 1: The Trinitarian Math (A Surprising Failure)
```
God - Father + Son = Christ
```
**Why it failed**: In Christian theology, subtracting the paternal context (`Father`) from God and adding the filial context (`Son`) should yield "`God` the `Son`". However, this failed across all three models (Qwen3 dropped to 0.666). The models exposed a linguistic reality of the KJV corpus: the word "son" is overwhelmingly generic ("a wise son," "son of David," "my son"). By adding the vector for "son," we accidentally injected massive amounts of generic human context, pulling the trajectory far away from `Christ`.


### Equation 2: The Soteriological Math (Threshold Broken)
