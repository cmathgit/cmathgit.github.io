Core Concepts & Definitions

To fully grasp the methodology of this research, we must first establish the foundational vocabulary of Distributional Semantics.

Distributional Semantics

The linguistic theory positing that words occurring in similar contexts tend to have similar meanings. In our research, this forms the theoretical bedrock for why neural networks cluster related tokens together.

Vector Embeddings

High-dimensional mathematical representations of human language. Rather than treating words as isolated strings, an LLM maps them into a dense spatial coordinate system (ranging from 768 to 1024 dimensions in this study).

Cosine Similarity

A statistical metric used to measure how similar two vectors are irrespective of their magnitude. It calculates the cosine of the angle between two vectors projected in multi-dimensional space, proving invaluable for semantic search as it ignores raw length and focuses purely on trajectory.

Semantic Bias & Geometric Drag

Phenomena occurring when generalized contexts skew mathematical precision within specialized semantic spaces. "Geometric drag" happens when heavily generalized words possess wide gravitational pulls, resisting precise mathematical isolation in niche use cases.

Objective & Hypotheses

The Objective: This project serves as a practical laboratory to verify the underlying geometry of LLM embeddings. We seek to empirically demonstrate why Cosine Similarity remains the undisputed industry standard for semantic search, whilst providing a masterclass in semantic bias. We intend to prove that when arithmetic perfectly aligns with highly specific contextual usage within a training corpus, an embedding model's spatial logic becomes brutally precise.

The Hypotheses:

  • Hypothesis I (The Control): Standard spatial relationships (e.g., King - Man + Woman = Queen) will hold true across different model architectures, validating basic semantic clustering algorithms.
  • Hypothesis II (The Theological Test): Applying spatial math to complex, contextually-dense theological concepts (culminating in an attempt to pinpoint the "Christ" vector using biblical corpus context, such as God - Father + Son) will reveal distinct geometric drag, emphasizing the semantic bias innate in generalized training data.

Replication Methodology

To guarantee the integrity of this case study, pre-calculated weights are intentionally omitted. Peer researchers must generate the raw semantic data directly from the models.

1. Clone the Repository

First, clone the source code repository containing the Python engine to your local machine:

git clone https://github.com/cmathgit/vector-math.git
cd vector-math

2. Model Acquisition

Download and install Ollama, then pull the required state-of-the-art embedding models to ensure cross-architecture validity:

ollama pull qwen3-embedding:0.6b
ollama pull embeddinggemma:300m
ollama pull granite-embedding:30m

3. Vector Generation

Generate JSON embedding files for 11 specific target tokens: King, Man, Woman, Queen, God, Christ, Father, Son, Jesus, Savior, Anointed.

Using native Windows CMD (cURL):

curl http://localhost:11434/api/embed -d "{\"model\": \"qwen3-embedding:0.6b\", \"input\": \"King\"}" > "embeddings/qwen3/king.json"
curl http://localhost:11434/api/embed -d "{\"model\": \"qwen3-embedding:0.6b\", \"input\": \"Man\"}" > "embeddings/qwen3/man.json"
curl http://localhost:11434/api/embed -d "{\"model\": \"qwen3-embedding:0.6b\", \"input\": \"Woman\"}" > "embeddings/qwen3/woman.json"

Repeat across all tokens and models. Alternatively, utilize Postman to POST to the /api/embed endpoint and save the raw JSON responses.

4. Mathematical Execution

Run the provided Python math engine (analyzeEmbeddings.py) to calculate resulting spatial coordinates using Cosine Similarity, Dot Product (Inner), Euclidean Distance (L2), and Manhattan Distance (L1).

python analyzeEmbeddings.py

Experimental Results: Successes & Failures

The Control Success: Classic Analogy

Our execution of the classic equation King - Man + Woman against the target Queen perfectly validated the efficacy of Cosine Similarity across architectures.

==================================================
Granite Ollama API METRIC ANALYSIS: Calculated vs Target 'Queen'
==================================================
1. Cosine Similarity: 0.863722
2. Dot Product: 0.936024
3. Euclidean Dist: 0.549890
4. Manhattan Dist: 11.907438

The Winner: IBM's Granite (768 dimensions) captured this specific semantic relationship most effectively, demonstrating the highest structural precision among the tested models.

The Theological Complexities (Failures & Insights)

When the engine was tasked with calculating highly abstract and contextually isolated concepts—specifically pinpointing the Christ vector—we encountered structural failures indicative of severe geometric drag.

  • Sparse Contextual Representation: While "King" and "Queen" share dense, uniform proximities in general web text, theological words like "Anointed" or "Savior" are heavily overloaded and sparse.
  • Mathematical Divergence: Attempts to calculate relationships like God - Father + Son yielded vectors that, while pointing generally toward the theological vicinity, suffered from significant L2 Distance expansion. The target vector became "stretched" by the generalized usages of terms like "Father" and "Son" outside of strictly biblical contexts.
  • Conclusion on Semantic Bias: The failure to achieve >0.9 Cosine Similarity for the theological vectors acts as proof that when a training corpus favors broad generalizations, highly specialized semantic arithmetic breaks down. It demonstrates why bespoke embeddings or Fine-Tuning are critical for domain-specific enterprise applications.
